BUG-083 Status tiket di DB tidak terupdate setelah Sales menutup tiket via Mobile
Critical High
▼
Environment
Staging — Mobile + MongoDB Compass
Module
Sales Flow / DB Consistency
Steps to Reproduce
  1. Login sebagai Sales di Mobile App
  2. Buka tiket aktif dengan status "In Progress"
  3. Klik tombol "Tutup Tiket" dan konfirmasi
  4. UI menampilkan status berubah menjadi "Closed"
  5. Cek dokumen tiket di MongoDB Compass via collection tickets
Expected Result
Field status di MongoDB berubah menjadi "closed" dan field closedAt terisi timestamp.
Actual Result
Di MongoDB, field status masih "in_progress" dan closedAt bernilai null. Data UI dan DB tidak konsisten.
DB Evidence

Ditemukan via MongoDB Compass — query filter { _id: ObjectId("...") } menunjukkan dokumen tidak terupdate meski response API mengembalikan status 200 OK. Indikasi race condition atau missing DB write di backend.

Validasi data langsung di MongoDB Compass — memastikan konsistensi antara UI, API response, dan data di database.

Case 1 — Ticket Status Consistency Check

UI Response (Frontend)
Status tampil: "Closed"
Timestamp penutupan tampil
Tombol "Tutup Tiket" hilang
MongoDB Compass (Database)
status: "in_progress" ← tidak sesuai
closedAt: null ← tidak terupdate
updatedAt: berubah (timestamp ada)
MongoDB Query — tickets collection db.tickets.findOne()
// Expected document after close action: { "_id": ObjectId("64f3a1b2c3d4e5f678901234"), "ticketCode": "TKT-2024-0083", "status": "closed", // ← expected "closedAt": ISODate("2025-12-10T09:30:00Z"), // ← expected "closedBy": "user_sales_id_456" } // Actual document found in DB: { "_id": ObjectId("64f3a1b2c3d4e5f678901234"), "ticketCode": "TKT-2024-0083", "status": "in_progress", // ← BUG: tidak terupdate "closedAt": null, // ← BUG: masih null "closedBy": null // ← BUG: masih null }
